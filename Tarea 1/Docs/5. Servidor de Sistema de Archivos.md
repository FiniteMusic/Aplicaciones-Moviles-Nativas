# 5. El servidor MCP de sistema de archivos (Filesystem)

## 5.1. Introducción

Un modelo de lenguaje puede interpretar solicitudes relacionadas con archivos, pero la generación de una respuesta no equivale a ejecutar operaciones sobre un sistema de archivos. Para realizar esas operaciones necesita una aplicación que le proporcione herramientas y un componente que efectúe las acciones autorizadas. El servidor MCP de sistema de archivos (*Filesystem MCP Server*) es una implementación de este mecanismo: expone funciones de lectura, escritura y administración de archivos mediante el Model Context Protocol (MCP).

## 5.2. ¿Qué significa «FS» y qué relación tiene con MCP?

La abreviatura **FS** procede de *filesystem* («sistema de archivos»). **No es una primitiva, una extensión obligatoria ni una parte independiente de la especificación de MCP.** Identifica el tipo de recurso con el que trabaja un servidor particular.

MCP es el protocolo de comunicación; el servidor Filesystem es una implementación que ofrece operaciones sobre archivos y directorios. Existen otros servidores MCP orientados a bases de datos, repositorios, servicios web u otras capacidades. Por tanto, dos servidores pueden implementar el mismo protocolo y ofrecer catálogos de herramientas diferentes.


## 5.3. ¿Cómo funciona el servidor Filesystem?

El funcionamiento puede describirse mediante la siguiente secuencia:

1. Una aplicación anfitriona establece una conexión con el servidor MCP mediante su cliente MCP.
2. El servidor comunica las herramientas disponibles y los esquemas de sus argumentos.
3. Ante una petición del usuario, la aplicación puede solicitar la ejecución de una herramienta apropiada.
4. El servidor valida la ruta y ejecuta la operación permitida sobre el sistema de archivos.
5. El resultado o el error vuelve a la aplicación mediante MCP para que pueda presentarse al usuario o utilizarse como contexto.

Por ejemplo, la solicitud «enumera los archivos de este directorio» puede traducirse en una llamada a `list_directory` con un argumento `path`. El servidor, no el modelo por sí solo, consulta el directorio y devuelve sus entradas.

**MCP estandariza el intercambio de solicitudes y resultados; las funciones concretas y sus efectos dependen de la implementación del servidor.**

## 5.4. Herramientas disponibles

| Herramienta | Función principal |
|---|---|
| `list_directory` | Enumera archivos y subdirectorios de una ruta autorizada. |
| `list_directory_with_sizes` | Enumera las entradas e incluye tamaños y estadísticas. |
| `directory_tree` | Devuelve una representación recursiva de la estructura de directorios. |
| `read_text_file` | Lee el contenido textual de un archivo; permite solicitar sus primeras o últimas líneas. |
| `read_media_file` | Lee contenido multimedia o binario y lo devuelve en un bloque de contenido apropiado. |
| `read_multiple_files` | Lee varios archivos en una misma operación. |
| `write_file` | Crea un archivo o sobrescribe por completo uno existente. |
| `edit_file` | Realiza modificaciones selectivas de texto y puede mostrar una vista previa de los cambios. |
| `create_directory` | Crea un directorio, incluidos directorios intermedios cuando se requieren. |
| `move_file` | Mueve o cambia el nombre de un archivo o directorio. |
| `search_files` | Busca recursivamente archivos y directorios cuyos nombres o rutas coinciden con patrones. |
| `get_file_info` | Obtiene metadatos, como tamaño, tipo, fechas y permisos. |
| `list_allowed_directories` | Muestra los directorios a los que el servidor tiene permitido acceder. |

### 5.4.1. Listar y leer

`list_directory` permite conocer el contenido inmediato de una carpeta; `directory_tree` ofrece una vista recursiva. Para inspeccionar el contenido de documentos de texto se utiliza `read_text_file`, mientras que `read_multiple_files` facilita recuperar varios archivos. Estas herramientas no deberían modificar el contenido de los archivos.

### 5.4.2. Crear, escribir y modificar

`create_directory` genera carpetas; `write_file` escribe contenido y **puede sobrescribir un archivo existente**; `edit_file` permite sustituir fragmentos concretos y admite una vista previa mediante `dryRun`. La diferencia es importante: escribir un archivo completo y editar una parte de su contenido no tienen el mismo riesgo de pérdida de información.

### 5.4.3. Mover y buscar

`move_file` permite cambiar una ruta o nombre dentro del ámbito autorizado. `search_files` busca coincidencias por patrones de nombres o rutas, incluidos patrones de tipo *glob*. **No debe confundirse con una búsqueda general de texto dentro del contenido de todos los archivos**: esa capacidad requeriría otra herramienta o una estrategia adicional de lectura y análisis.

## 5.5. Directorios permitidos: delimitación del alcance

El servidor Filesystem aplica un conjunto de **directorios permitidos** (*allowed directories*). Las operaciones sobre archivos y carpetas deben quedar dentro de ese conjunto. Sus subdirectorios también pueden ser accesibles, siempre que no se vulneren las comprobaciones de rutas.

La documentación oficial describe dos vías para establecer los directorios permitidos:

- **Argumentos de inicio:** se indican las rutas autorizadas al ejecutar el servidor.
- **Roots del cliente:** en clientes y versiones que admiten esta capacidad, el cliente puede comunicar rutas al servidor y actualizar el conjunto autorizado.

### Ejemplo conceptual

Supóngase que el servidor tiene permitido acceder únicamente a:

```text
C:\Datos\DocumentosAutorizados
```

En ese caso, una lectura de `C:\Datos\DocumentosAutorizados\informe.txt` puede admitirse, mientras que una solicitud de `C:\Datos\Privado\claves.txt` debe rechazarse por quedar fuera del alcance definido. Este ejemplo ilustra el principio de delimitación; la respuesta exacta depende de la implementación y del sistema operativo.

## 5.6. ¿Por qué existe este límite?

El límite de directorios aplica el principio de **mínimo privilegio**: una herramienta debe disponer únicamente del acceso necesario para cumplir su función. Si se autorizara la raíz de un disco o todo el directorio personal, un error de interpretación, una solicitud ambigua o una instrucción maliciosa podrían alcanzar información ajena a la tarea.

Sin delimitación adecuada podrían producirse, entre otros efectos:

- Lectura de documentos confidenciales o archivos con credenciales.
- Sobrescritura de archivos importantes mediante `write_file`.
- Modificación o traslado de archivos que otras aplicaciones necesitan.
- Exposición de una superficie de acceso mucho mayor ante instrucciones maliciosas incorporadas en documentos.

La restricción de rutas reduce el impacto potencial de estas situaciones, pero **no sustituye** los permisos del sistema operativo, la confirmación humana para acciones sensibles ni la revisión de las herramientas habilitadas.

## 5.7. Validación de rutas y límites de la protección

Un servidor seguro no debe limitarse a comprobar si una cadena comienza con el nombre de una carpeta. También necesita contemplar rutas relativas, componentes como `..` y enlaces simbólicos que puedan conducir fuera de los directorios permitidos. La implementación oficial incluye funciones de validación de rutas y resolución de rutas reales para aplicar su política de acceso (Model Context Protocol, s. f.-b).

Es necesario distinguir entre dos niveles de protección:

1. **Restricción implementada por el servidor:** decide qué rutas acepta una herramienta MCP.
2. **Permisos del sistema operativo o aislamiento del proceso:** determinan qué puede hacer realmente el proceso, incluso si una aplicación presenta fallas.

El primero reduce el alcance de las herramientas; el segundo aporta una barrera adicional. Autorizar un directorio no implica que todos sus archivos sean necesariamente legibles o modificables: los permisos del sistema operativo también pueden impedir una operación.

## 5.8. Conclusión

El servidor MCP Filesystem permite convertir solicitudes relacionadas con archivos en operaciones ejecutadas por un componente especializado. Su valor técnico consiste en publicar herramientas comprensibles para una aplicación con IA sin otorgar al modelo acceso directo al sistema operativo.

La característica central de seguridad es la delimitación de los directorios permitidos, acompañada de validación de rutas y de los permisos efectivos del proceso. Esta protección debe entenderse como parte de una estrategia más amplia de control de acceso y supervisión de operaciones potencialmente destructivas.
