# 7. Casos de uso del Model Context Protocol (MCP)

## 7.1. Introducción

El Model Context Protocol (MCP) permite que distintas aplicaciones de inteligencia artificial se comuniquen con servidores que exponen herramientas, recursos y plantillas de prompt. Su utilidad no se limita al acceso a archivos: puede conectar asistentes con repositorios de código, bases de datos, servicios web y plataformas de trabajo. En los entornos de desarrollo, facilita que un asistente consulte información actualizada y solicite operaciones sobre recursos que una aplicación o un servidor tiene autorizados (Model Context Protocol, s. f.).

## 7.2. Herramientas que implementan MCP

### 7.2.1. Visual Studio Code con GitHub Copilot

Visual Studio Code es un editor y entorno de desarrollo extensible. Su integración con asistentes de programación permite configurar servidores MCP para ampliar las herramientas disponibles durante una conversación de trabajo. Un servidor puede ofrecer operaciones de consulta o modificación de archivos, búsqueda en servicios externos y acceso a documentación técnica.

**Caso de uso:** un asistente puede consultar información expuesta por un servidor MCP, relacionarla con el código abierto en el editor y proponer o ejecutar acciones de desarrollo sujetas a las autorizaciones configuradas. La edición ordinaria de archivos del espacio de trabajo también puede realizarse mediante capacidades nativas del asistente: no toda modificación de código en VS Code ocurre necesariamente a través de MCP (Model Context Protocol, s. f.; Model Context Protocol, s. f.-b).

### 7.2.2. Cursor

Cursor es un editor de código con funciones de inteligencia artificial. Su documentación oficial indica que admite servidores MCP para conectar al agente con herramientas y fuentes de datos externas. Los servidores pueden configurarse mediante un archivo `mcp.json` y proporcionar capacidades locales o remotas (Cursor, s. f.).

**Caso de uso:** un agente puede consultar datos de un servicio conectado, localizar información necesaria para una modificación de software y utilizar las herramientas disponibles para completar una tarea. Cursor muestra las herramientas MCP y contempla mecanismos de aprobación de su ejecución, de acuerdo con la configuración del usuario (Cursor, s. f.).

### 7.2.3. Zed

Zed es un editor de código que incorpora funciones de asistencia mediante modelos de lenguaje. Su documentación describe el uso de MCP para conectarse con servidores de contexto; el agente de Zed puede utilizar directamente los servidores configurados. La documentación consultada señala soporte para herramientas y plantillas de prompt, así como actualización de la lista de herramientas cuando un servidor notifica cambios (Zed Industries, s. f.).

**Caso de uso:** un agente puede consultar herramientas externas mientras trabaja con código en el editor. Por ejemplo, un servidor de archivos puede ofrecer funciones para leer información o buscar documentos autorizados, mientras otro servidor podría proporcionar acceso a un servicio de desarrollo.

### 7.2.4. Claude Code

Claude Code es una herramienta de asistencia para programación que puede conectarse con servidores MCP. Su utilidad consiste en ampliar las capacidades del agente mediante herramientas externas y fuentes de contexto. El SDK oficial de MCP identifica a Claude Code entre las aplicaciones anfitrionas que pueden conectarse a servidores del protocolo (Model Context Protocol, s. f.).

**Caso de uso:** un asistente puede combinar el contexto del código con información procedente de herramientas conectadas, como documentación o servicios de gestión del desarrollo. Conviene distinguir las herramientas nativas de Claude Code de aquellas incorporadas específicamente mediante MCP.

## 7.3. Comparación de aplicaciones

| Herramienta | Tipo de aplicación | Uso de MCP | Ejemplo de integración |
|---|---|---|---|
| Visual Studio Code con GitHub Copilot | Editor de código con asistente | Incorporar herramientas de servidores externos. | Consultar un servidor de archivos o un servicio de documentación. |
| Cursor | Editor de código con agente de IA | Conectar fuentes de datos y herramientas locales o remotas. | Consultar un servicio externo durante una tarea de programación. |
| Zed | Editor de código con agente | Utilizar servidores de contexto mediante MCP. | Consultar herramientas de un servidor configurado. |
| Claude Code | Asistente de programación | Ampliar las herramientas y fuentes de información del agente. | Recuperar información de servicios conectados. |

La compatibilidad con MCP no implica que todas las aplicaciones implementen todas las características opcionales del protocolo ni que tengan idénticas políticas de autorización. La cobertura concreta debe verificarse en la documentación de cada producto y versión.

## 7.4. ¿Cómo pueden trabajar con repositorios completos sin subir cada archivo manualmente?

En un entorno de desarrollo local, el editor o asistente puede tener acceso al espacio de trabajo abierto y, cuando se configura un servidor de sistema de archivos, este puede exponer operaciones sobre los directorios autorizados. El flujo general es el siguiente:

1. La persona abre un repositorio en su entorno de desarrollo o autoriza una carpeta determinada.
2. La aplicación anfitriona identifica las herramientas disponibles, incluidas las que expone un servidor MCP conectado.
3. El modelo interpreta la tarea y selecciona herramientas adecuadas, como listar directorios, buscar nombres de archivo o leer contenido.
4. El servidor ejecuta las operaciones permitidas y devuelve sus resultados a la aplicación.
5. Con esa información, el asistente puede solicitar modificaciones en archivos concretos, sujetas a los permisos y mecanismos de aprobación correspondientes.

Así, no es necesario adjuntar manualmente cada archivo en una conversación. El contexto puede recuperarse de manera selectiva a través de las capacidades del editor y de los servidores conectados. Esto **no significa** que todo el repositorio se envíe automáticamente al modelo ni que el modelo tenga acceso directo e ilimitado al disco: la información accesible depende de las herramientas, del alcance autorizado y de las decisiones de la aplicación anfitriona (Model Context Protocol, s. f.-b).

## 7.5. MCP y las herramientas nativas de los editores

Es importante no atribuir a MCP todas las funciones de un asistente de programación. Un editor puede leer, buscar o modificar archivos mediante sus propias herramientas integradas, sin utilizar un servidor MCP. MCP agrega una interfaz estandarizada para descubrir y utilizar capacidades proporcionadas por servidores conectados. En consecuencia, el acceso a un repositorio puede resultar de una combinación de funciones nativas, permisos del entorno y herramientas MCP.

Tampoco deben confundirse los modelos con las aplicaciones que los utilizan: **Qwen es una familia de modelos**, mientras que un editor, una herramienta de línea de comandos o un agente concreto constituye la aplicación que podría implementar MCP.

## 7.6. Conclusión

MCP favorece la interoperabilidad entre aplicaciones de inteligencia artificial y servicios externos. En el desarrollo de software, permite incorporar herramientas para consultar archivos, documentación y sistemas relacionados con el ciclo de vida del código. Visual Studio Code, Cursor, Zed y Claude Code ilustran distintas formas de utilizar estas integraciones. Su aportación principal es ofrecer una vía común para poner capacidades a disposición de un asistente, sin confundir el protocolo con las herramientas nativas del editor ni con un acceso irrestricto a los recursos locales.
